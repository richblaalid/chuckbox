# BSA Reference Data Files

This directory contains the canonical BSA (Boy Scouts of America) reference data used by the Chuckbox application.

## Source of Truth

### Primary Data Files (Used by Seeder)

| File | Purpose | Used By |
|------|---------|---------|
| `bsa-data-canonical-normalized.json` | **PRIMARY** - Merit badges AND ranks with versioned requirements, proper hierarchy | `bsa-reference-data.ts` seeder |
| `leadership-positions-2025.json` | Leadership positions (18 positions) | `bsa-reference-data.ts` seeder |

### Secondary Data Files

| File | Purpose | Notes |
|------|---------|-------|
| `bsa-data-canonical.json` | Copy of normalized file for backwards compatibility | Legacy scripts |
| `merit-badge-requirements-scraped.json` | Raw scraped data from BSA website | Fallback import, flat structure |
| `merit-badges-canonical.json` | Badge metadata (images, categories) | Used by scraped import for metadata |
| `scoutbook-requirement-ids.json` | Mapping of requirement IDs from Scoutbook exports | Reference for sync compatibility |
| `requirement-fixes.json` | Registry of fix scripts and known issues | Used by `fix-bsa-requirements.ts` |
| `validation-report.json` | Latest validation results | Generated by `validate-bsa-structure.ts` |

## Data Structure

### bsa-data-canonical-normalized.json

This file contains ALL BSA reference data: merit badges and ranks.

```json
{
  "merit_badges": [
    {
      "name": "Badge Name",
      "category": "Category",
      "image_url": "/merit-badges/badge-name.png",
      "versions": [
        {
          "version_year": 2025,
          "requirements": [
            {
              "requirement_number": "1",     // UI display number
              "scoutbook_id": "1",           // Scoutbook sync ID (DO NOT CHANGE)
              "description": "...",
              "is_header": true,
              "children": [...]
            }
          ]
        }
      ]
    }
  ],
  "ranks": [
    {
      "code": "TENDERFOOT",
      "name": "Tenderfoot",
      "description": "...",
      "display_order": 2,
      "is_eagle_required": true,
      "requirement_version_year": 2022,
      "versions": [
        {
          "version_year": 2022,
          "requirements": [
            {
              "requirement_number": "1a",
              "description": "...",
              "is_header": false,
              "display_order": 1,
              "children": []
            }
          ]
        }
      ]
    }
  ]
}
```

### Key Fields

- **requirement_number**: Normalized for UI display (e.g., `4A(1)(a)`)
- **scoutbook_id**: Original ID from Scoutbook CSV exports - **NEVER MODIFY** (required for sync)
- **is_header**: `true` if this requirement has children, `false` if completable
- **children**: Nested array of sub-requirements
- **display_order**: Order for displaying requirements in the UI

## Modifying Data

### To fix requirement structure issues:

1. Edit `bsa-data-canonical-normalized.json` directly
2. Copy changes to `bsa-data-canonical.json`: `cp bsa-data-canonical-normalized.json bsa-data-canonical.json`
3. Run `npm run db:fresh` to verify

### Rules:

- **NEVER change `scoutbook_id` values** - these sync with Scoutbook
- **DO change `requirement_number`** for UI display
- **DO change `is_header` and `children`** to fix hierarchy
- Always run `npm run db:fresh` after changes to verify

## Seeding Commands

```bash
npm run db:fresh          # Reset DB and seed all data
npm run db:seed:bsa       # Seed only BSA reference data

# Manual seeding (individual commands)
npx tsx scripts/bsa-reference-data.ts import-all            # Ranks + leadership positions
npx tsx scripts/bsa-reference-data.ts import-canonical-ranks # Ranks only
npx tsx scripts/bsa-reference-data.ts import-canonical-reqs  # Merit badges only
npx tsx scripts/bsa-reference-data.ts import-positions      # Leadership positions only
```

## Validation

After any changes to canonical data, run validation:

```bash
npm run db:fresh    # Full reset + seed + validate
npx tsx scripts/validate-bsa-structure.ts   # Validate only
```

The validator checks for:
- Empty headers (headers with no children)
- Orphaned requirements (children without valid parent)
- Inconsistent nesting depths
- Duplicate requirement numbers
